# Dataset Analysis and Reverse Engineering Report

## Goal
Analyze the dataset at `/home/user/work/codex-dataset/output/fixed_test/dataset.jsonl` to identify quality issues and reverse engineer the generation pipeline to find the root causes.

## Identified Issues in Dataset

### 1. Impossible/Invalid Numeric Values
- **Symptom**: `device_count` appearing as floating point numbers (e.g., "1.1 devices").
- **Root Cause**: `DiversityAgent._extract_kpis_from_context` uses a regex `(\d+(?:\.\d+)?)` which extracts floats from the corpus without validating if the metric should be an integer.
- **Location**: `src/tmf921_dataset_gen/agents/diversity.py:99`

### 2. Logic Errors in Constraint Operators
- **Symptom**: Reliability constraints using `atMost` instead of `atLeast` (e.g., "reliability at most 99.92%").
- **Root Cause**: `semantic_frame.infer_operator` uses a keyword-based approach. If the generated `nl_intent` contains "below", "under", or "less than", it assigns `at_most` regardless of whether the metric (like reliability) logically requires a minimum.
- **Location**: `src/tmf921_dataset_gen/validation/semantic_frame.py:151`

### 3. Mismatch Between NL Intent and TMF921 Payload
- **Symptom**: The TMF921 payload contains constraints (KPIs) that are completely absent from the `nl_intent` text.
- **Root Cause**: 
    - The pipeline generates a set of KPIs first.
    - These KPIs are used to build the `intent_frame` and the TMF921 payload.
    - The `nl_intent` is rendered from a template or rewritten by an LLM using these KPIs.
    - If the template or LLM omits some KPIs, the payload still contains them because it's built from the `intent_frame`, not the final `nl_intent` text.
- **Location**: `src/tmf921_dataset_gen/graph/workflow.py` (Workflow orchestrates this sequence).

### 4. Unrealistic KPI Values
- **Symptom**: Critical intents with extremely low reliability (e.g., "30%").
- **Root Cause**: `DiversityAgent._extract_kpis_from_context` pulls values directly from the retrieved corpus. If the corpus contains unrealistic values, they are used. `semantic_score.extract_kpis` only checks if reliability is between 0 and 100, not if it's realistic for a "critical" intent.
- **Location**: `src/tmf921_dataset_gen/agents/diversity.py:102` and `src/tmf921_dataset_gen/validation/semantic_score.py:87`

### 5. Critic Validation Gap
- **Symptom**: The above issues are not caught by the `CriticRefinementAgent` and the records are marked as `accepted`.
- **Root Cause**: The critic's primary acceptance mechanism (`symbolic_pass`) calls `verify_semantic_alignment`, which compares the **TMF921 payload** against the **intent_frame**. Since both are derived from the same KPI set, they match perfectly, even if neither matches the `nl_intent` text.
- **Location**: `src/tmf921_dataset_gen/agents/critic.py:114-118` and `src/tmf921_dataset_gen/validation/semantic_frame.py:390`

## Reverse Engineered Pipeline Flow
1. **Retrieval**: Get context from corpus based on taxonomy.
2. **Diversification**: 
    - Extract KPIs from context or sample them.
    - Render a baseline `nl_intent` using templates.
    - Optionally rewrite `nl_intent` using an LLM.
3. **Translation**:
    - Build an `intent_frame` by merging extracted/sampled KPIs and inferring operators from the `nl_intent`.
    - Generate TMF921 payload from the `intent_frame`.
4. **Critique**:
    - Validate payload schema and TIO compliance.
    - Compare payload vs `intent_frame` (Symbolic check).
    - Ground claims against corpus.
    - If all pass, accept the record.
