# Plan for Codebase Review: TMF921 Dataset Generator

## Overview
The TMF921 Dataset Generator is a Python-based project that creates synthetic datasets pairing natural-language intent expressions with structured TMF921 v5.0 Intent_FVO payloads for telecom intent-based networking (IBNA) systems. The review will verify truthfulness, scientific/logical validity of all components, and assess if the project is State-of-the-Art (SOTA) and publishable.

## Key Claims to Verify
- 100% schema and TIO (Topology-Independent Ontology?) compliance
- 100% semantic pass rate via symbolic equivalence
- 0% phantom constraints, 0% operator inversions
- Aggregate metrics: 67% semantic preservation, 0.86 quality score
- Novel synthetic intent corpora for telecom domain
- Research-grade pipeline with reproducible local generation

## Review Steps

### 1. Verify TMF921 Specification Compliance
- **Fetch and review TMF921 v5.0 specification documents** from TM Forum (using webfetch/websearch for official specs, conformance profiles).
- **Examine Intent_FVO structure**: Confirm what Intent_FVO (Formal Validation Object?) entails and if the payloads match.
- **Cross-check generated payloads**: Sample payloads from output datasets against spec schemas (JSON-LD/Turtle formats).
- **Check parsers and ingestion**: Verify that input corpus (OAS/Postman, TR290 docs) is correctly parsed and integrated.

### 2. Code Correctness and Logical Validity
- **Read core modules**:
  - `src/tmf921_dataset_gen/` (agents: diversity, translator, critic; ingestion; RAG; validation; export)
  - Focus on generator logic, RAG implementation (ChromaDB), LLM usage (Qwen 3.5 9B).
- **Review validation stack**: 5-layer verifier (schema, TIO structural, symbolic semantic equivalence, evidence-grounding, LLM tie-breaker).
- **Check for logical errors**: Ensure no false positives/negatives in equivalence checks, proper error handling.
- **Run unit/integration tests**: Execute `tests/` to verify functionality.
- **Assess reproducibility**: Check if pipeline produces consistent results with same seeds.

### 3. Data Quality and Validity
- **Use provided dataset**: The user provided `/home/user/work/codex-dataset/thousand_records_dataset/dataset.jsonl` as generated from current codebase.
- **Examine input corpus**: ~189 documents – verify sources and normalization.
- **Sample output datasets**: Use the provided dataset to check for compliance, semantic accuracy.
- **Run benchmark scripts**: `benchmarks/` to validate quality claims (semantic preservation, quality scores) on this dataset.
- **Manual spot checks**: Review 10-20 random pairs from provided dataset for logical consistency between NL intent and TMF921 payload.
- **Bias and diversity**: Assess diversity prompts for mitigating biases.

### 4. Scientific Soundness
- **Evaluate methodology**: RAG grounding, local LLM usage, validation metrics.
- **Check for scientific rigor**: Audit trails, release gates (≥95% semantic pass), evidence maps.
- **Compare to known methods**: Use codesearch/websearch for similar synthetic dataset generation techniques in telecom/NLP.
- **Ethical considerations**: Verify transparency, synthetic nature disclosure, TMF compliance.

### 5. Assess State-of-the-Art (SOTA) Status
- **Literature review**: Search for recent papers on synthetic datasets for intent-based networking, TMF specs, or telecom NLU.
- **Compare to existing work**: Is this novel? (Local generation without APIs, comprehensive validation, telecom-specific.)
- **Technological edge**: GPU acceleration, modular pipeline, Hugging Face integration.
- **Limitations**: Identify gaps (e.g., multi-lingual support mentioned as future).

### 6. Assess Publishability
- **Novelty**: Does it advance the field? (New corpora, methods.)
- **Correctness**: Based on verification above, are claims substantiated?
- **Impact**: Potential for ML training, benchmarking in telecom.
- **Reproducibility**: Open source, documented pipeline.
- **Venue suitability**: Academic (e.g., telecom conferences, NLP venues) or industry (TM Forum publications).
