# Evaluation Plan: Should codex_upgrade_plan.md be implemented?

## Overview
The codex_upgrade_plan.md proposes upgrading the TMF921 NL Intent to TMF921 Intent dataset generation pipeline from a schema-valid synthetic generator to a research-grade system with stronger semantic guarantees, evidence-grounding, and release-quality evaluation.

## Current System Analysis
- The existing pipeline (src/tmf921_dataset_gen/) is already sophisticated with agents, RAG, validation layers
- Critic agent performs schema validation, semantic scoring, symbolic alignment, evidence attribution, TIO compliance, realism scoring
- Quality metrics show average scores around 0.81, but plan identifies potential false positives and acceptance of semantically inconsistent records

## Plan Assessment

### Strengths of the Upgrade Plan
1. **Symbolic Verification Priority**: Shifting from heuristic/LLM-primary to symbolic semantic equivalence checks as the foundation, with LLM as secondary tie-breaker
2. **Intermediate Representations**: Explicit intent_frame, constraint_set, tmf921_payload separation ensures traceable derivation from NL intent
3. **Rigorous Rejection Criteria**: Clear requirements to reject records with missing constraints, wrong operators, contradictory names/context, mismatched semantics
4. **Evidence Attribution**: Replacing realism score with traceable grounding to retrieved chunks, with separate synthetic vs grounded modes
5. **Dataset Release Gates**: Manual audit samples, benchmark suites, semantic preservation thresholds for production releases
6. **Methodology Alignment**: Claims limited to validated behavior, not overpromising

### Potential Concerns
1. **Implementation Complexity**: Significant refactoring required across agents, validation, and export modules
2. **Performance Impact**: Layered verification stack may slow generation, especially with symbolic checks
3. **LLM Dependency Reduction**: Plan reduces LLM trust, but current system relies heavily on LLM hints for generation
4. **Backward Compatibility**: New metadata fields added, but existing dataset.jsonl structure preserved where possible

### Risks if Not Implemented
- Dataset may contain false positives with semantic inconsistencies
- Claims of "strict adherence" or "ensures grounding" remain undefensible
- Research users may encounter unreliable training data
- Continued acceptance of records with omitted constraints or wrong expectation types

## Recommendation
**IMPLEMENT THE UPGRADE PLAN**

### Rationale
1. The current system has foundational components that align well with the plan's architecture
2. The plan addresses critical gaps for research-grade quality assurance
3. Benefits (semantic guarantees, defensible claims, audit gates) outweigh implementation complexity
4. Aligns with stated goals of research-grade dataset production

### Implementation Approach
1. Phase 1: Core verifier stack (symbolic checks primary, LLM secondary)
2. Phase 2: Intermediate representation pipeline (intent_frame, constraint_set)
3. Phase 3: Grounding modes and evidence attribution
4. Phase 4: Dataset audit gates and benchmark suites
5. Phase 5: Documentation and methodology updates

### Success Criteria
- Previously identified false positives rejected (from output/1k_qwen_gpu_fullpower/dataset.jsonl examples)
- Benchmark suite passes with high semantic preservation rates
- Manual audit shows >95% acceptance on valid cases, 0% on hard negatives
- Methodology claims backed by explicit evidence from audits
